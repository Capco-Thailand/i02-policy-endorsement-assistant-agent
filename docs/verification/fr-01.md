## Red and green evidence

- Auth suite: `npm run test:api -- src/auth/auth.test.ts` first failed because session implementation was absent; after implementation, 5 tests passed.
- Proposal guard: `npm run test:api -- src/policies/policies.test.ts` failed with `authorizeProposalDecision is not a function`; after adding the server-loaded record guard, 4 tests passed.
- Sign-in form: `npm run test:web -- src/app/sign-in/SignInForm.test.tsx` initially failed because the form was absent; implementation passed 3 tests. A later explicit POST method check failed with a missing `method` attribute, then passed.
- Sign-out and navigation: `npm run test:web -- src/components/SignOutButton.test.tsx src/lib/navigation.test.ts` initially failed because the components were absent, then passed 2 tests. The protected cache check subsequently failed with cached policy data still present, then passed after cache clearing.
- Sign-out API failure: `npm run test:web -- src/components/SignOutButton.test.tsx` failed because a `503` still produced a signed-out notice; a retryable inline error then passed without falsely claiming revocation.
- Response validation: `npm run test:web -- src/lib/api.test.ts` failed because a malformed policy response was accepted; schema validation then passed.
- CORS: `npm run test:api -- src/auth/auth.test.ts` failed because the alternate loopback origin was still allowed; the localhost-only default then passed.
- OpenAPI accuracy: the contract test failed because sign-in advertised an unimplemented `429`; removing that response passed.
- Protected heading focus: `npm run test:web -- src/components/FocusHeading.test.tsx` initially failed because the heading behavior was absent, then passed.
- Sign-in mutation cache isolation: `npm run test:web -- src/app/sign-in/SignInForm.test.tsx` failed because prior protected query data remained after sign-in; using a TanStack Query mutation and clearing cached data before navigation passed all 4 form tests.
- Expiry route: `npm run test:web -- src/app/policies/page.test.tsx` passed on addition against existing route behavior. This is a verification-only test, so no behavior-changing red step applied.
- Password hash typing: removing the unchecked scrypt cast caused the API TypeScript build to fail on `unknown`; a runtime Buffer check restored a passing build without changing expected authentication behavior.
- Request logging: `npm exec --workspace @pea/api -- vitest run src/auth/auth.test.ts` failed because no request log was emitted; after enabling Fastify logging with cookie and authorization header redaction, all 6 focused auth tests passed.

## Live API and browser checks

With API on port 3000 and Next.js on port 3001, a live HTTP round trip returned `401` before login, `200` for Alice sign-in and her policy, identical `404` bodies for Bob's and an unknown policy, `204` for sign-out, and `401` after sign-out. Chrome showed a generic invalid-credential error, then Alice's two linked policies after valid sign-in, an unavailable result at Bob's direct policy URL, and the signed-out notice without protected data after sign-out. A second browser run signed in as Bob, showed only `SYN-POL-2001`, returned the unavailable page for Alice's direct policy URL, and showed the signed-out notice. The protected heading received focus after Alice's sign-in.

For live expiry, the API ran with a file-backed test clock through its existing `now` injection. Alice signed in through the browser; after the clock advanced 31 minutes, reloading `/policies` redirected to `/sign-in?returnTo=%2Fpolicies&reason=expired`, showed “Your session ended. Sign in again to continue,” and showed no policy data. At a 320px browser viewport, the sign-in page had `clientWidth` and `scrollWidth` both equal to 320 and no horizontal overflow. The viewport override was reset afterward.
